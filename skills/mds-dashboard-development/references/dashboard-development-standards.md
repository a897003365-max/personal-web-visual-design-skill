# 数据看板开发规范

本规范由用户逐项确认，维护日期为 2026-10-28。适用于 mads.ren 的数据看板、相关明细页，以及为它们服务的共享组件和读取接口。

本文件集中维护已确认的全部规范，不预设条款总数。已有编号保持稳定，新增条目顺延；修订时同步更新入口、交叉引用和开发检查清单。项目入口见[项目上下文](project-context.md)，执行步骤见[开发流程](development-workflow.md#dashboard-workflow)。

当前用户明确要求及本规范优先于历史实现记录。与本规范冲突的旧口径、旧样式进入独立待整改记录，不作为默认例外。本文描述开发与验收要求，不代表现有页面已全部符合。

<a id="rule-01"></a>
## 1. 官方区间去重

- 区间人数及依赖人数计算的指标，使用同一业务范围、同一日期区间的官方去重数据。
- 缺少对应官方区间数据时，明确显示缺失或“区间待补”；不以每日人数相加、每日比率平均或其他范围的数据替代。
- 转化率、点击率、客单价等涉及人数的指标，分子也必须覆盖同一区间。单日真实值可独立展示，并注明日期，不能冒充区间值。

<a id="rule-02"></a>
## 2. 真实零、缺失、负数和部分数据

- 真实零显示 `0`，负值保留原值和负号。
- 缺失显示 `—`，按实际情况说明“尚未采集”“区间待补”“加载失败”等原因，不补零。
- 金额、件数等可加指标只有部分数据时，可展示“已知合计”，并标明覆盖范围，例如“6/7 天”；不作为完整期间结果。
- 人数及其派生指标继续遵循[官方区间去重](#rule-01)，不能用部分日记录拼成完整区间结果。

<a id="rule-03"></a>
## 3. 比率使用对应分子、分母计算

- 费比、退款率、ROI 等，按共同有效记录分别汇总分子、分母后相除，不直接平均每日比率。
- 分子、分母匹配同一店铺／账号、日期范围和业务口径；部分覆盖明确标注。
- 转化率、客单价等涉及人数的指标，使用[第 1 条](#rule-01)规定的官方区间去重人数及同区间分子。
- 分母为零或缺少必需数据时显示 `—`；分子确实为零且分母有效时，结果才为零。

<a id="rule-04"></a>
## 4. 同比、环比及变化语义

- 环比使用紧邻的上一等长周期；同比使用去年同月同日。未满月比较截至同一天，2 月 29 日没有对应日期时保留缺失。
- 两期保持相同店铺、账号和业务口径，按共同有效日期比较并注明可比天数；本期主值保留原统计范围。区间去重指标的两期都须有对应的官方区间数据。
- 金额、数量显示百分比变化；费比、退款率、转化率、点击率显示百分点变化；ROI 显示倍数差。
- 百分比增幅仅在基期大于零时计算；基期为零、负值或缺失时显示 `—` 并说明原因。
- 变化文案依据指标的业务方向生成：

| 指标方向 | 示例 | 数值增加 | 数值减少 |
|---|---|---|---|
| 越低越好 | 费比、退款率、获客成本、响应时长 | 上升 | 下降 |
| 越高越好 | 转化率、点击率、ROI | 提升 | 下降 |
| 无法直接判断好坏 | 按具体业务定义的中性指标 | 增加 | 减少 |

例如：退款率从 10% 到 12% 显示“上升 2 个百分点”；转化率同样变化显示“提升 2 个百分点”。ROI 从 3 到 4 显示“提升 1.00x（倍数差）”，不写成“提升 1 倍”。

<a id="rule-05"></a>
## 5. 日期筛选与默认周期

- 首次进入各数据看板默认显示近 7 天，以本模块最新有效业务日为截止日，包含截止日在内连续 7 个自然日；起止日期都计入。
- 缺失日期保留在所选范围内，不自动缩短区间。“近 7 个数据日”与“近 7 天”分别标明；近 30 天、活动全程等作为可选范围。
- 用户手动选择日期后，切换看板内部页签和自动刷新保留当前选择。
- 顶部日期默认控制整页；月度趋势、分时对比等采用独立范围时，明确标注作用范围，局部选择不改变全局日期。
- 活动计划可以展示未来日期；未来实际数据保持缺失，不填零。
- 业务日期、数据采集／入库时间、页面最近读取时间分别标注，不互相代替。

<a id="rule-06"></a>
## 6. 数值与单位展示

- 原始数值严格大于 `10000` 时除以 `10000`，以“万”展示；等于或小于 `10000` 时保留原单位。
- 保留业务单位：元对应万元、人对应万人、件对应万件；不混用 K、M，也不自动改为“亿”。
- 指标卡、表格、图表坐标、标签和提示框遵循同一换算规则，单位与数值对应。
- 同一指标采用统一精度规则，同列小数位一致，负值保留负号。
- 换算仅影响展示，存储、接口、计算、排序、筛选和数据导出保留原始值。
- 示例：`10,000 元 → 10,000 元`；`12,345 元 → 1.23 万元`。验收覆盖 `10000` 及其上下边界。

<a id="rule-07"></a>
## 7. 页面布局、视觉层级与默认配色体系

- 顶部集中放置页面标题、日期、店铺／账号筛选和数据状态；同类控件的位置一致。
- 内容通常按“关键结果 → 趋势与构成 → 明细”组织，专题页沿用已确认的业务顺序。
- 同级模块统一左右边线、标题基线、内边距和间距；并排比较的图表保持绘图区对齐。
- 重点指标通过位置、字号、尺寸和配色共同突出，可使用数值强调色、卡片背景色及明暗对比建立主次。重点强调色与涨跌状态色分工明确。
- 长表格和复杂图表按需占满一行，保证阅读空间。局部改版明确影响范围，避免样式波及其他模块。
- 默认配色体系使用 [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)，调色实施与检查使用 `impeccable / colorize`。先读取适用 Skill 和现有配色，再复用语义颜色管理重点指标、背景、文字、交互状态和图表。
- 核验实际文字与背景的对比度，颜色配合文字或符号表达含义。Radix Colors 提供色板，`impeccable / colorize` 承担调色流程。

<a id="rule-08"></a>
## 8. 颜色表达改善、恶化与中性

| 指标方向 | 数值增加 | 数值减少 |
|---|---|---|
| 费比、退款率、成本等越低越好 | 暖红色，文案“上升” | 青绿色，文案“下降” |
| 转化率、点击率、ROI 等越高越好 | 青绿色，文案“提升” | 暖红色，文案“下降” |

- 使用 Radix 的 Teal 表示改善、Tomato 表示恶化、Amber 表示待关注、Slate 表示中性或无可比结论。
- 图表中指标、渠道的固定配色保持稳定；涨跌状态色用于变化提示。
- 颜色同时配合文字、箭头或符号。持平、缺失和无可比结论继续通过文案和值区分。

<a id="rule-09"></a>
## 9. 字体、字号与数字排版

- 字体与层级采用用户确认的“标题厚实、数字醒目、表格紧凑”版本。中文使用 [Noto Sans SC](https://fontsource.org/fonts/noto-sans-sc/about)，数字和英文使用 [Barlow Semi Condensed](https://fontsource.org/fonts/barlow-semi-condensed/about)。
- 字体通过 Fontsource 获取后由网站自托管，按需加载所用字重和中文分片，保留随字体提供的许可证。
- 采用统一的角色层级，同级内容使用一致字号、字重和语义颜色。默认标尺来自已确认样张：

| 角色 | 字体 | 默认字号 | 字重 |
|---|---|---|---|
| 页面标题 | Noto Sans SC | 24px；窄屏 22px | 700 |
| 模块标题 | Noto Sans SC | 16px | 600 |
| 正文 | Noto Sans SC | 14px | 400／500 |
| 指标名称 | Noto Sans SC | 14px | 600 |
| 筛选范围、数值单位 | Noto Sans SC | 13px | 500 |
| 表头 | Noto Sans SC | 12px | 600 |
| 核心指标数值 | Barlow Semi Condensed | 46px | 700 |
| 次级指标数值 | Barlow Semi Condensed | 36px | 600 |
| 表格数值 | Barlow Semi Condensed | 18px | 600 |
| 变化提示中的数值 | Barlow Semi Condensed | 16px | 600 |
| 辅助说明、变化提示文字 | Noto Sans SC | 12–13px | 400／500 |

- 数值开启 `font-variant-numeric: tabular-nums`，减少位数变化造成的跳动。指标卡的单位紧邻数值、字号较小、沿基线对齐。
- 同比、环比、统计范围和覆盖信息采用次级视觉层级，同时保持清晰可读。
- 长商品名可省略显示，并提供完整名称提示；关键指标名称、单位和正负号完整可见。
- 响应式调整遵循[第 21 条](#rule-21)，同一角色同步调整，保持主次关系。

<a id="rule-10"></a>
## 10. 表格对齐、列宽、行距与留白

- 文字默认左对齐，数值右对齐，日期、序号和状态居中；末级表头与对应列内容一致，多级分组表头居中。
- 同列采用相同精度和单位展示规则，换算为“万”时单位随数值明确显示。
- 商品名称等信息列保留足够空间，指标列宽稳定，避免刷新或排序后整表跳动。
- 同级行统一高度和内边距；长文本换行时保持整行对齐。
- 合计、小计行通过适度加粗或浅色底区分，并与明细列严格对齐。
- 表格边缘与内容之间保留统一留白，首末列、表头和最后一行不贴边。桌面左右内边距默认 16px，窄屏不少于 12px；上下留白与所在卡片协调。表头、明细和合计行使用相同的左右对齐线。

<a id="rule-11"></a>
## 11. 长表格冻结与滚动

- 纵向滚动固定表头，多级表头整组固定。
- 横向长表默认冻结商品、店铺等关键识别列，查看右侧指标时仍能辨认对象。
- 表头与冻结列交叉处层级正确、底色不透明，避免文字重叠或底层内容透出。
- 宽表在自身区域横向滚动，保持列宽与字号可读；滚动范围清楚，避免多层滚动互相干扰。
- 下拉菜单、日期选择器和提示浮窗完整显示，不被表格滚动容器裁切。

<a id="rule-12"></a>
## 12. 排序、分页与合计

- 可排序列提供明确入口，显示当前排序列及升降序，使用原始数值排序。
- 先对完整筛选结果排序，再分页；缺失值排在最后，相同值的顺序保持稳定。
- 分页区位于表格底部，明确显示总条数、当前页和每页条数。
- 汇总卡、合计行覆盖完整筛选范围；需要展示当前页小计时明确标为“本页小计”。
- 切换店铺、日期或筛选条件后回到第一页，同时保留仍适用的排序和列配置。

<a id="rule-13"></a>
## 13. 商品、SKU 与图片灯箱

- 点击商品行可展开／收起 SKU，并用箭头明确标示状态。
- SKU 子行通过缩进或浅色背景体现层级，数值列与父表表头严格对齐。
- 父表与 SKU 的共同指标使用相同排序方向。
- 展开时按当前店铺、日期和来源读取对应 SKU；加载中、无数据、读取失败分别显示在该商品的展开区域。
- 点击商品或 SKU 图片打开灯箱大图，按原比例完整显示并适配当前屏幕。支持关闭按钮、Esc 和点击遮罩关闭，关闭后恢复原焦点与滚动位置。
- 图片点击只打开灯箱，不触发行展开、收起或选品；商品链接及操作按钮也只执行对应操作。
- 缺图显示占位，图片加载失败给出明确提示。

<a id="rule-14"></a>
## 14. 图表数值、坐标与图例显隐

- 日期轴保留完整区间；缺失值断线，真实零绘制为零，负值保留负向位置。
- 只有一个有效观测点时显示单点；全部无数据时显示明确空态。
- 坐标轴标明指标与单位；用于直接比较的并排图表采用一致的单位和标尺。
- 普通比较柱形图、比例条以零为基线；瀑布图按[第 16 条](#rule-16)表达累计加减关系。百分比指标不自动限定在 0%–100%；固定坐标范围按已确认的业务要求设置，原始值仍完整可查，不通过截断数值实现固定轴。
- 数据密集时调整绘图区、间距与标签位置，按[第 26 条](#rule-26)保留数据标签；标签和刻度保持可读，避免文字重叠、裁切。
- 点击图例显示／隐藏对应数据系列；同一图例关联的本期与同期数据同步处理。
- 曲线或柱形、数据点、标签和悬浮提示同步显隐；非固定坐标轴按可见数据更新范围。
- 隐藏项在图例中明确弱化，再次点击即可恢复。全部隐藏时显示“已隐藏全部系列”，并提供恢复入口。

<a id="rule-15"></a>
## 15. 图表提示浮窗

- 显示系列名称、实际日期或统计区间、数值及单位；对比数据明确标出对应期间。
- 多系列按稳定顺序排列，名称左对齐、数值右对齐；本期与同期分栏对齐。
- 浮窗避让当前数据点，靠近边缘时自动调整位置，不越出可视区或被容器裁切。
- 内容过长时允许在浮窗内滚动，保持文字可读，首尾内容均可查看。
- 桌面悬停、触屏点击、键盘聚焦均可查看，并能方便关闭。

<a id="rule-16"></a>
## 16. 图表类型与业务含义

- 时间变化使用趋势图；排名、大小比较优先使用条形图，名称较长时采用横向条形图。
- 堆叠图只组合可相加的分项，避免把父级汇总与子项重复堆叠。
- 瀑布图清楚表达加减关系，末列等于所展示分项的合计；部分数据标为“已知分项合计”。
- 占比图明确分母；交叉归因、重叠人群不能展示成互斥的去重人数构成。
- 占比分项达到 4 项及以上时采用南丁格尔玫瑰图，1–3 项采用圆饼图；无有效数据时按[第 14 条](#rule-14)展示空态。
- 南丁格尔玫瑰图以扇区面积表达数值比例，图例和提示显示真实值；不能把数值直接当半径而放大差异。
- 不同量纲优先分图；确需双轴时明确左右轴对应关系，超过两种量纲时拆为共享日期轴的上下图。

<a id="rule-17"></a>
## 17. 指标与列配置

- 配置面板区分“可选”和“已选”，按业务分组；字段较多时支持搜索。
- 已选指标或列支持调整顺序，页面按确认后的顺序展示。
- 修改先作为草稿，点击“确定”才应用；“取消”不生效，“恢复默认”也需确认后应用。
- 商品、笔记等必要识别列始终保留，确保每行数据能对应到具体对象。
- 已确认的配置按看板保存，刷新、切换日期后保留；新增指标不覆盖用户已有选择。

<a id="rule-18"></a>
## 18. 加载、刷新与过期响应

- 首次加载使用骨架或明确占位，数值不先显示为零。
- 切换日期、店铺、账号或来源后撤下旧范围结果；旧请求的成功、失败响应都不能覆盖当前结果。
- 同范围自动刷新保留有效数据，不重置页签、排序、图例选择、展开状态和滚动位置。
- 读取失败明确说明并提供手动重试；保留上次成功数据时，同时标明数据时间和刷新失败状态。

<a id="rule-19"></a>
## 19. 按需加载与相关模块更新

- 首次只加载当前页签；商品、SKU、竞品等详情在打开时读取，翻页不重复加载无关模块。
- 相同条件的请求尽量复用；缓存区分日期、店铺／账号、来源、商品等影响结果的条件。
- 运营总览、天猫明细、抖音明细沿用已接入的数据库通知、SSE 与版本检查；数据变化后更新相关模块，机制见[看板更新契约](database/dashboard-live-events.md)。
- 其他看板按各自已确认的策略刷新，不统一添加高频轮询。
- 页面隐藏时减少无用读取，恢复时检查并补充新数据，同时遵循[第 18 条](#rule-18)保留操作状态。

<a id="rule-20"></a>
## 20. 交互动效与键盘操作

- 普通反馈动效控制在 150–250ms，非加载动效最长 300ms。
- 指标立即显示最终数值，动效用于状态切换和层级反馈。
- 尊重系统“减少动态效果”设置；切换页面或筛选时取消旧动效。
- 核心控件支持键盘操作，焦点清晰；弹窗支持 Esc 关闭并恢复原焦点。

<a id="rule-21"></a>
## 21. 桌面与窄屏适配

- 至少检查 1440px、1024px、390px 三种宽度。
- 筛选栏合理换行，指标卡调整列数；宽表局部横向滚动，图表随容器调整。
- 标题、单位、按钮、日历和浮窗不得遮挡、裁切或超出可视区。
- 同时检查独立页面和主站导航容器内的效果。
- 浏览器窄屏模拟与真机验收分别记录，不互相代替。

<a id="rule-22"></a>
## 22. 数据来源与权限边界

- 每项指标明确来源、字段、粒度、店铺／账号范围、业务日期、单位和计算公式。
- 快照类指标按已确认的快照规则取值，禁止跨日期、跨对象拼接数值填补缺失。
- 页面与接口都执行权限校验；看板读取保持只读，人工标注等编辑功能使用独立权限和写入入口。
- 页面刷新不擅自启动采集、修改源数据或数据库结构。
- 凭据和真实连接信息不进入页面、日志及规范文件。

<a id="rule-23"></a>
## 23. 按实际行为和数据验收

- 按改动范围执行检查、构建和相关回归；行为改动需独立审查，纯规范文档可自查。
- 数据口径用官方来源或独立只读查询核对，覆盖缺失、零、负值、零分母、部分覆盖及 `10000` 换算边界。
- 浏览器验证受影响的真实操作，包括快速切换、排序分页、SKU、灯箱、图例、浮窗、配置和刷新。
- 测试绑定实际提交或文件快照；修改后重新验证受影响范围。
- 分别记录已验证、未验证和残余问题。构建成功或健康接口正常不能代替页面验收，合成数据检查与真实来源核对分别记录。

<a id="rule-24"></a>
## 24. 集中维护并接入开发流程

- 将已确认的全部规范集中维护在本文件，不固定条款总数。已有编号保持稳定，新增条目顺延，并同步更新目录、交叉引用和开发检查清单。
- 项目级 `AGENTS.md` 保留入口和关键约束，开发流程引用对应检查点，不复制整份正文。
- 开发前明确本次涉及哪些规范，交付时按适用条目验收；修改共享组件时检查受影响的看板。
- 工作规范仅在本地维护并纳入 Git 忽略；规范-only 修改不触发提交、推送或部署。
- 现有页面与新规范的差异另列待整改清单。规范落地与代码整改分别记录，不将规范更新表述为页面行为已经改变。

<a id="rule-25"></a>
## 25. 看板注释与说明保持克制

- 本条适用于指标说明、统计口径、图表注释及数据状态提示，只解释重点逻辑和必要信息。
- 重点解释去重范围、退款归属、比较方式、特殊计算等容易误读的内容。
- 影响当前读数判断的缺失、部分覆盖等状态直接简短标明；详细口径放入提示浮窗或可展开说明。
- 使用业务语言和短句，一条说明一个要点，通常一句即可；技术字段、实现细节留在开发文档。
- 共用口径集中说明，指标特有差异就近补充，避免在每张卡、每行数据中重复。
- 示例：“退款按退款发生日统计。”

<a id="rule-26"></a>
## 26. 生产数据图表必须附带数据标签

- 所有生产、交付的数据图表必须默认显示数据标签，直接呈现对应数值；坐标刻度、图例和悬浮提示不能代替数据标签，悬浮提示作为补充。
- 标签与对应的柱形、条形、数据点、扇区或瀑布分项关联清楚；占比图显示占比。数值、单位和精度遵循[第 6 条](#rule-06)，真实零和负值保留，缺失数据不生成虚假零值标签。
- 标签保持清晰可读，不重叠、不遮挡关键图形、不被裁切。数据密集时通过调整布局、绘图区、标签位置或引导线解决，不以直接关闭数据标签处理拥挤。
- 筛选、日期、指标或图例显隐变化时，数据标签与对应数据同步更新和显隐。
- 验收覆盖不悬停时的默认显示、标签与实际数值的一致性，以及桌面和窄屏下的可读性。数据标签属于必要数值展示，与[第 25 条](#rule-25)的解释性注释区分。
